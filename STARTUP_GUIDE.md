# AtlasBot Trading System - Startup Guide

This guide will help you start the AtlasBot trading system with paper trading through the UI.

## Prerequisites

1. **Environment Variables**: Make sure your API keys are set in the environment (already done based on your screenshot)

2. **Install Dependencies**:
   ```bash
   # Install frontend dependencies
   npm install

   # Install backend dependencies
   cd atlas/apps/core-node
   pnpm install
   ```

## Starting the System

You need to run 3 services:

### 1. Start the Backend API Server (Terminal 1)
```bash
cd atlas/apps/core-node
pnpm api
```

This will start the API server on `http://localhost:3001` with:
- HTTP API endpoints
- WebSocket for real-time updates
- Connection to Coinbase API
- Supabase integration

### 2. Start the Frontend (Terminal 2)
```bash
# From the project root
npm run dev
```

This will start the Vite dev server on `http://localhost:5173`

### 3. Seed the Database (One-time setup)

Run this SQL in your Supabase SQL editor:

```sql
-- Seed symbols table with tradable markets
INSERT INTO symbols (symbol, base_asset, quote_asset, tick_size, lot_size, active) 
VALUES 
  ('BTC-USD', 'BTC', 'USD', 0.01, 0.0001, true),
  ('ETH-USD', 'ETH', 'USD', 0.01, 0.001, true)
ON CONFLICT (symbol) DO UPDATE SET
  tick_size = EXCLUDED.tick_size,
  lot_size = EXCLUDED.lot_size,
  active = EXCLUDED.active;
```

## Using the System

1. **Open the UI**: Navigate to `http://localhost:5173` in your browser

2. **Start Paper Trading**:
   - Click the "Start" button in the header
   - The system will connect to Coinbase and start paper trading
   - You'll see "Connected" badge when the WebSocket is active

3. **Monitor Activity**:
   - **Positions Panel**: Shows open positions with real-time P&L
   - **Metrics Grid**: Displays account metrics and performance
   - **Signals Panel**: Shows trading signals generated by strategies
   - **Risk Controls**: Manage risk parameters

4. **Stop Trading**:
   - Click "Pause" to stop the trading engine
   - Use "Kill Switch" for emergency stop (closes all positions)

## Features in Paper Trading Mode

- ✅ Real-time market data from Coinbase
- ✅ Signal generation (Breakout, VWAP Mean Reversion strategies)
- ✅ Simulated order execution with realistic fills
- ✅ Position tracking with P&L calculation
- ✅ Risk management and position limits
- ✅ WebSocket updates to UI
- ✅ Data persistence in Supabase

## Troubleshooting

1. **"Disconnected" Status**:
   - Make sure the API server is running (`pnpm api`)
   - Check the browser console for WebSocket errors

2. **No Market Data**:
   - Verify your Coinbase API credentials are correct
   - Check the API server logs for connection errors

3. **Database Errors**:
   - Ensure Supabase credentials are set correctly
   - Run the seed SQL to create necessary symbols

## Architecture Overview

```
Frontend (React) ←→ API Server ←→ Trading Engine
    ↓                   ↓              ↓
Supabase DB      WebSocket      Coinbase API
```

The system uses:
- **Frontend**: React + Vite for the UI
- **API Server**: Express + WebSocket for real-time communication
- **Trading Engine**: Core trading logic with paper trading simulator
- **Supabase**: PostgreSQL database with real-time subscriptions
- **Coinbase**: Market data and order execution (simulated in paper mode)

## Next Steps

Once paper trading is working:
1. Monitor the performance and signals
2. Adjust risk parameters as needed
3. Review trades in the positions panel
4. Check logs for any errors or issues

When ready for live trading:
1. Ensure you have sufficient funds in Coinbase
2. Update the mode from 'paper' to 'live' in the config
3. Start with small position sizes
4. Monitor closely and use the kill switch if needed
